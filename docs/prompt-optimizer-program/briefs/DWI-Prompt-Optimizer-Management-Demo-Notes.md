# DWI Prompt Optimizer — Management Brief Presenter Notes

## Core message

DWI is a local proof of concept for a project-aware operating layer that makes AI-assisted work more consistent and reviewable. It brings approved project knowledge, structured task intent, transparent composition and human control into one interaction contract.

The proposed future direction extends that contract—after the baseline is stable—with optional PMS task metadata, a policy-governed token-budget envelope and consented content-free feedback. These are future extensions, not current implementation or qualification claims.

## Slide-by-slide emphasis

### 1. A project-aware operating layer

Open with the management outcome: consistent, governed AI-assisted delivery. Separate the current POC from the future operating model immediately.

### 2. The management problem

The issue is not merely prompt quality. Fragmented AI interactions create repeated briefing, inconsistent outputs, unclear resource use and weak decision-ready feedback.

### 3. A repeatable structure

Use four verbs: bring together, structure, resolve and review. DWI can expose a material gap today. The one-question answer, skip and safe application sequence remains a target extension.

### 4. A concrete example

A generic answer may look polished while missing local deployment or rollback rules. The current POC grounds the task and exposes uncertainty before review.

### 5. Current benefits

Emphasize less repeated briefing, fewer omissions, lower cognitive load, clearer review, consistent project knowledge and explicit human control.

### 6. Local demonstration

Demonstrate only what is supported now: reviewed Project Meta Context, structured task details, visible sources and assumptions, local composition, save and scoped reset. Do not present the focused answer/application flow as complete.

### 7. Future operating direction

Explain the proposed chain:

1. An optional PMS adapter supplies minimal approved sprint or task metadata.
2. A DWI governance policy maps that metadata to a capped budget envelope.
3. The internal composition engine uses the envelope to allocate approved context and composition depth.
4. The developer reviews, corrects, accepts or resets the result.
5. Consented content-free outcome signals are aggregated to improve policy, enablement and process.

Budget is a bounded input, not spending authority. Feedback is for operating improvement, not employee surveillance.

### 8. Management objective areas

Connect each audience to its decisions:

- Developer: improve clarity, workflow and cognitive load.
- Team: strengthen knowledge reuse, handoffs and delivery consistency.
- SDLC operations: identify stage friction, fallback, latency and budget adherence.
- Management or AI CoE: direct enablement and investment, plan capacity and govern responsible scale.

Reporting should aggregate by workflow or cohort, exclude raw prompts and project content, and prohibit individual ranking.

### 9. Recommended decision path

Ask management to evaluate usefulness and sponsor a staged evidence plan—not to declare production or release readiness. Experience the POC, close the baseline, freeze governance, run offline or shadow allocation and only then pilot one bounded workflow.
